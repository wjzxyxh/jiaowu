# 教务管理系统 — 使用说明

本文说明如何在本地或服务器上**启动、停止、访问**本系统，以及 **「教师课时」** 模块中与**全职底薪**相关的规则。

---

## 一、架构说明

| 组件 | 说明 | 默认端口 |
|------|------|----------|
| **后端** | Flask（入口：`app.py`，蓝图在 `routes/`） | **5000** |
| **前端** | React + Vite（目录：`frontend/`） | **3000** |

开发环境下，前端通过 Vite 将 **`/api` 请求代理到 `http://localhost:5000`**（见 `frontend/vite.config.js`）。

生产环境可将前端 `npm run build` 后的静态资源交给 Nginx，或由 Flask 托管静态文件，并把 API 指到同一域名下的 `/api`。

---

## 二、环境要求

- **Python 3**（建议 3.9+），并已安装项目依赖（`requirements.txt` 等，按你方部署方式安装）。
- **Node.js**（建议 18+）、**npm**，用于前端开发与构建。

数据库默认使用项目根目录下的 **SQLite**（如 `jiaowu.db`，以实际配置为准）。

---

## 三、启动服务（开发模式）

### 1. 启动后端

在项目根目录执行：

```bash
cd /path/to/pycharm_project_231
python3 app.py
```

- 默认监听 **`0.0.0.0:5000`**。
- 可通过环境变量 **`PORT`** 指定端口，例如：`PORT=5001 python3 app.py`。
- 配置名可通过 **`FLASK_CONFIG`** 指定（见 `app.py`），生产环境需正确设置 **`SECRET_KEY`**。

### 2. 启动前端

```bash
cd /path/to/pycharm_project_231/frontend
npm install   # 首次或依赖变更时
npm run dev -- --host 0.0.0.0 --port 3000
```

- 浏览器访问：**`http://<服务器IP>:3000`**
- 教师课时页面路径示例：**`/teacher-hours`**

### 3. 仅访问 API（不启前端）

直接请求后端，例如：

```text
http://<服务器IP>:5000/api/teacher-hours?month=2026-03&employment_type=全职
```

## 四、停止与重启

### 方式 A：在运行终端按 `Ctrl+C`

分别在后端、前端的终端窗口停止对应进程。

### 方式 B：按端口结束进程（Linux）

```bash
# 结束占用 5000、3000 的进程（需有权限）
fuser -k -n tcp 5000
fuser -k -n tcp 3000
```

然后按「第三节」重新启动后端与前端。

> **提示**：若提示 `Address already in use`，说明端口仍被占用，需先释放端口再启动。

## 五、「教师课时」功能说明

### 1. 页面入口

- 前端：**教师课时**（路由 `/teacher-hours`）。
- 分 **全职** / **兼职** 两个标签；数据来自接口 **`GET /api/teacher-hours`**，可带参数：
  - `month`：月份，格式 `YYYY-MM`
  - `employment_type`：`全职` 或 `兼职`

### 2. 统计规则（摘要）

- 仅统计 **已确认** 的排课（`is_confirmed == true`）。
- **正常** 计 1 课时；**跑空** 计 0.5 课时；**请假** 等按业务规则不计入实际课时。
- 总工资一般包含：**课时费 + 经验 + 底薪（仅全职）+ 激励**（以后端计算为准）。

### 3. 全职老师「无排课也要结算底薪」

业务要求：**全职老师即使当月没有已确认排课，只要配置了底薪，也应出现在列表中并可结算。**

实现要点：

1. 系统会自动使用一门 **停用** 的占位课程：**「底薪(占位)」**（科目：`系统`），为符合条件的全职老师在对应月份创建一条 **课时为 0** 的 `TeacherHours` 记录，用于：
   - 显示底薪与总工资；
   - **确认结算 / 取消结算**；
   - 编辑 **激励、备注**（与其它课时行一致）。
2. **仅当** 教师在 **教师档案** 中 **`employment_type = 全职`** 且 **`base_salary > 0`** 时，才会自动出现这条「无排课底薪」行（避免底薪为 0 的无效数据）。
3. 在 **「全职」** 标签下，若当月确实无上课记录，**上课时间** 列会显示「暂无上课记录」，但 **底薪、总工资** 仍应正确。

### 4. 财务汇总中的老师成本

更新收支表时，老师工资按 **教师维度汇总**，避免 `TeacherHours` 按课程多行导致 **底薪、激励、经验、课时费被重复累计**。  
无排课但有底薪的全职教师，其底薪也会计入当月 **老师成本**（在重新计算/更新财务记录时生效）。

## 六、生产部署建议（简要）

1. 后端使用 **gunicorn / uwsgi** 等托管，前面加 **Nginx** 反向代理与 HTTPS。
2. 设置 **`FLASK_CONFIG=production`** 与安全的 **`SECRET_KEY`**。
3. 前端执行 **`npm run build`**，将 `frontend/dist` 交给 Nginx 或合并进后端静态目录。
4. 定期备份数据库文件与上传目录（见 `app.py` 中 `UPLOAD_FOLDER` 配置）。
5. **备份到阿里云 OSS**：见 [`docs/阿里云OSS数据库备份.md`](阿里云OSS数据库备份.md)（脚本 `scripts/backup_db_to_oss.py`；**自动备份**用 `scripts/run_oss_backup.sh` + systemd timer 或 crontab）。

## 七、常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 前端能开但接口 502/404 | 后端未启动或端口不一致 | 确认 `5000` 上后端正常；检查 Vite `proxy` |
| 端口被占用 | 旧进程未退出 | 见第四节释放端口 |
| 全职有底薪但列表没有 | 未选「全职」标签、底薪为 0、或教师非启用状态 | 检查教师档案底薪与雇佣类型 |
| 修改代码未生效 | 未重启后端 | 重启 `python3 app.py`（开发模式有 reloader，视情况而定） |
